## A. Problem from Dolgoderevenskoye

### Problem in short

Given `x`, there is one card for every positive divisor of `x`. Two players alternate, Artem first. On the first move any card may be removed. After that, each card removed must have the =(accent)opposite parity= of the previous one. The player who cannot move loses. Does Artem win?

### Idea

#### Step 1: count the cards by parity

Write `x = 2^a · m` with `m` odd, and let `d(m)` be the number of divisors of `m`.

- Odd divisors are exactly the divisors of `m`, so there are `d(m)` odd cards.
- Every even divisor has the form `2^j · (divisor of m)` with `1 <= j <= a`, so there are `a · d(m)` even cards.

#### Step 2: the parity sequence is forced

After Artem picks the parity of his first card, every later move has a forced parity: odd, even, odd, even, … or the other way round. The cards themselves do not matter, only whether a pile runs out. Let `O` be the number of odd cards and `E` the number of even cards.

- If Artem starts with odd, the evens run out first when `O > E`. After `E` even cards are gone, Artem takes one more odd card and the second player is stuck. With `O <= E` Artem is the one who gets stuck.
- If Artem starts with even, he wins exactly when `E > O`.

So Artem wins whenever `O != E`, and he loses only when `O = E`.

#### Step 3: when are the counts equal?

`O = E` means `d(m) = a · d(m)`, so `a = 1`. That is the same as `x ≡ 2 (mod 4)`.

=(ok)**answer = "No" if `x % 4 == 2`, otherwise "Yes"**=

Samples:

| `x` | `a` | odd cards | even cards | answer |
|-----|-----|-----------|------------|--------|
| 1 | 0 | 1 | 0 | Yes |
| 2 | 1 | 1 | 1 | No |
| 6 | 1 | 2 | 2 | No |
| 12 | 2 | 2 | 4 | Yes |
| 8 | 3 | 1 | 3 | Yes |
| 74 | 1 | 2 | 2 | No |

> =(info)**Note.**= For odd `x` we have `a = 0`, so there are no even cards at all. Artem takes an odd card and the second player cannot answer, so the answer is `Yes`.

### Code

```cpp
#include <bits/stdc++.h>
int main()
{
    int t;
    std::cin >> t;
    while (t--)
    {
        long long x;
        std::cin >> x;
        std::cout << (x % 4 == 2 ? "No" : "Yes") << std::endl;
    }
    return 0;
}
```

### Walkthrough

- `t` : the number of test cases.
- `x` : the given number, up to `10^18`.
- `x % 4 == 2` : true exactly when `x` has one factor of `2`, which is the only losing case.
- The ternary prints `"No"` in that case and `"Yes"` otherwise.

> =(warn)**Warning.**= `x` goes up to `10^18`, so it must be `long long`. A 32-bit `int` would overflow while reading.

> =(ok)**Tip.**= You never need to factor `x`. Only the exponent of `2` matters, and it is `1` exactly when the remainder modulo `4` is `2`.

**Complexity:** =(accent)O(1)= time per test and =(accent)O(1)= memory.

## B. Problem from Chebarkul

### Problem in short

Given an array `a` of length `n` and an integer `k`, count the positions `i` in `1..k` such that every subsequence of length `k` has the same number at position `i`.

### Idea

#### Step 1: which elements can land on position `i`?

In a subsequence of length `k`, the element at position `i` is some `a[j]`. There must be `i - 1` chosen elements before it and `k - i` after it, so `i <= j <= n - k + i`.

That is a window of exactly `w = n - k + 1` consecutive elements, starting at `i`.

#### Step 2: when is the value always the same?

Every element of the window can really be chosen for position `i`, so the value is the same in all subsequences exactly when =(accent)all `w` elements of the window are equal=.

#### Step 3: check windows with run lengths

Let `running[j]` be the length of the block of equal values that ends at `j`:

`running[j] = running[j - 1] + 1` if `a[j] == a[j - 1]`, otherwise `1`.

The window `a[i..i + w - 1]` is constant exactly when `running[i + w - 1] >= w`. So

=(ok)**answer = number of `i` in `1..k` with `running[i + w - 1] >= w`**=

Samples:

| Test | `n, k` | `w` | `running` | good `i` | answer |
|------|--------|-----|-----------|----------|--------|
| `1 1 1 1` | 4, 2 | 3 | 1, 2, 3, 4 | `i = 1, 2` | 2 |
| `1 2 1 2` | 4, 2 | 3 | 1, 1, 1, 1 | none | 0 |
| `1 2 2 2 5` | 5, 3 | 3 | 1, 1, 2, 3, 1 | `i = 2` | 1 |
| `1 1 2 2 1 1` | 6, 5 | 2 | 1, 2, 1, 2, 1, 2 | `i = 1, 3, 5` | 3 |

> =(info)**Note.**= When `k = n` we get `w = 1`, so every window is a single element and every position counts. The fifth sample gives `4`.

### Code

```cpp
#include <bits/stdc++.h>
int main()
{
    int t;
    std::cin >> t;
    while (t--)
    {
        int n, k;
        std::cin >> n >> k;
        std::vector<int> a(n + 1), running(n + 1, 0);
        for (int i = 1; i <= n; i++)
        {
            std::cin >> a[i];
            running[i] = (i > 1 && a[i] == a[i - 1]) ? running[i - 1] + 1 : 1;
        }
        int w = n - k + 1, result = 0;
        for (int i = 1; i <= k; i++)
            if (running[i + w - 1] >= w)
                result++;
        std::cout << result << std::endl;
    }
    return 0;
}
```

### Walkthrough

- `n`, `k` : the array length and the subsequence length.
- `a` : the array, stored from index `1`.
- `running[i]` : the length of the block of equal values ending at `i`. It is built while reading the input.
- `w = n - k + 1` : the window size from Step 1.
- `result` : the number of good positions.
- **Loop over `i` from `1` to `k`:** the window ends at `i + w - 1`. If `running` there is at least `w`, the whole window is one value, so `result` goes up.

> =(warn)**Warning.**= The last window ends at `k + w - 1 = n`, so the index never goes out of bounds. That is why `running` only needs size `n + 1`.

> =(ok)**Tip.**= No sliding-window structure is needed. A single run-length array answers "is this window constant?" in `O(1)`.

**Complexity:** =(accent)O(n)= time per test and =(accent)O(n)= memory.

## C. Problem from Ust-Katav

### Problem in short

Given a permutation `p` of length `n`, a subarray is =(ok)good= if no other subarray of the same length has the same minimum value. Count the good subarrays.

### Idea

#### Step 1: one minimum, one position

Because `p` is a permutation, a minimum value identifies one position. So we can handle each element `p[i]` on its own: look at all subarrays whose minimum is `p[i]`, and count those that are the only one of their length.

#### Step 2: the range where `p[i]` is the minimum

Let `l[i]` be the index of the previous smaller element (`0` if none) and `r[i]` the index of the next smaller element (`n + 1` if none). Put

- `a = i - l[i]` : how many left endpoints are possible,
- `b = r[i] - i` : how many right endpoints are possible.

The subarrays with minimum `p[i]` have lengths `1` to `a + b - 1`. For a given length `len`, the number of them is

`min(len, a, b, a + b - len)`

#### Step 3: when is that number exactly 1?

- If `min(a, b) = 1`, then every length from `1` to `a + b - 1` has exactly one subarray. All `a + b - 1` of them are good.
- If `min(a, b) >= 2`, only `len = 1` and `len = a + b - 1` give a count of `1`. These two lengths are different, so exactly `2` subarrays are good.

=(ok)**answer = sum over `i` of ( `a + b - 1` if `min(a, b) == 1`, otherwise `2` )**=

Sample 4 (`3 7 5 1 6 4 2`):

| `i` | `p[i]` | `l` | `r` | `a` | `b` | contribution |
|-----|--------|-----|-----|-----|-----|--------------|
| 1 | 3 | 0 | 4 | 1 | 3 | 3 |
| 2 | 7 | 1 | 3 | 1 | 1 | 1 |
| 3 | 5 | 1 | 4 | 2 | 1 | 2 |
| 4 | 1 | 0 | 8 | 4 | 4 | 2 |
| 5 | 6 | 4 | 6 | 1 | 1 | 1 |
| 6 | 4 | 4 | 7 | 2 | 1 | 2 |
| 7 | 2 | 4 | 8 | 3 | 1 | 3 |

The total is `3 + 1 + 2 + 2 + 1 + 2 + 3 =` =(ok)**14**=.

> =(info)**Note.**= In sample 3 (`3 2 4 1`) the contributions are `1, 2, 1, 4`, which add up to `8`. The two subarrays with minimum `2` and length `2` are `[3, 2]` and `[2, 4]`, so neither is good.

### Code

```cpp
#include <bits/stdc++.h>
int main() {
    int t;
    std::cin >> t;
    while (t--) {
        int n;
        std::cin >> n;
        std::vector<int> p(n + 2), l(n + 2), r(n + 2);
        for (int i = 1; i <= n; i++) std::cin >> p[i];
        
        std::vector<int> state;
        for (int i = 1; i <= n; i++) {
            while (!state.empty() && p[state.back()] > p[i]) state.pop_back();
            l[i] = state.empty() ? 0 : state.back();
            state.push_back(i);
        }
        state.clear();

        for (int i = n; i >= 1; i--) {
            while (!state.empty() && p[state.back()] > p[i]) state.pop_back();
            r[i] = state.empty() ? n + 1 : state.back();
            state.push_back(i);
        }

        long long result = 0;
        for (int i = 1; i <= n; i++) {
            long long a = i - l[i], b = r[i] - i;
            if (std::min(a, b) == 1) result += a + b - 1;
            else result += 2;
        }
        std::cout << result << std::endl;
    }
    return 0;
}
```

### Walkthrough

- `p` : the permutation, from index `1`.
- `l[i]` : index of the previous smaller element, `0` if there is none.
- `r[i]` : index of the next smaller element, `n + 1` if there is none.
- `state` : a monotonic stack of indices whose values increase from bottom to top.
- **First pass (left to right):** pop every index whose value is larger than `p[i]`. What is left on top is the previous smaller element, so it is stored in `l[i]`. Then push `i`.
- **Second pass (right to left):** the same idea gives the next smaller element in `r[i]`. `state` is cleared in between.
- `a`, `b` : the number of possible left and right endpoints for the minimum `p[i]`.
- `result` : adds `a + b - 1` when `min(a, b) == 1`, otherwise `2`.

> =(warn)**Warning.**= `result` must be `long long`. The answer can be close to the number of all subarrays, about `n(n+1)/2`, which is around `2 × 10^10` for `n = 2 × 10^5`.

> =(ok)**Tip.**= The stack pops strictly larger values only. Since all values in a permutation are distinct, no ties can happen, so strict versus non-strict makes no difference.

**Complexity:** =(accent)O(n)= time per test (each index is pushed and popped once per pass) and =(accent)O(n)= memory.

## D. Problem from Yuzhnouralsk

### Problem in short

Given an array `a`, one operation picks an index `i` with `2 <= i <= n` and, at the same time, adds `a[i]` to `a[i - 1]`, adds `a[i]` to `a[i + 1]` (if `i < n`) and replaces `a[i]` by `-a[i]`. Make all elements nonnegative with the minimum number of operations, or print `-1` if it is impossible.

### Idea

#### Step 1: look at prefix sums

Let `s[j] = a[1] + … + a[j]` and `s[0] = 0`. An operation at `i` gives

- new `s[i - 1] = s[i - 2] + a[i - 1] + a[i] =` old `s[i]`,
- new `s[i] =` new `s[i - 1] - a[i] =` old `s[i - 1]`,
- every other prefix sum stays the same, including `s[i + 1]`.

So an operation is exactly =(accent)a swap of two neighbouring prefix sums `s[i - 1]` and `s[i]`=. Since `i >= 2`, the value `s[0] = 0` is never touched, and every adjacent pair among `s[1..n]` can be swapped.

#### Step 2: what does "all nonnegative" mean?

`a[1] = s[1] - 0` and `a[j] = s[j] - s[j - 1]`, so all elements are nonnegative exactly when

`0 <= s[1] <= s[2] <= … <= s[n]`

#### Step 3: feasibility and the count

- Swaps only reorder `s[1..n]`, so the set of values never changes. If some `s[j] < 0`, the smallest value would sit at the front and be negative, so the answer is `-1`.
- Otherwise the goal is to sort `s[1..n]` using adjacent swaps. The minimum number of adjacent swaps is the =(ok)number of inversions=, which are the pairs `i < j` with `s[i] > s[j]`. Equal values are not inversions.

=(ok)**answer = `-1` if any prefix sum is negative, otherwise the inversion count of the prefix sums**=

The inversion count is computed with merge sort.

Samples:

| Test | prefix sums `s` | any negative? | inversions | answer |
|------|-----------------|---------------|------------|--------|
| `1 -1 2` | 1, 0, 2 | no | 1 | `1` |
| `-1 3` | -1, 2 | yes | - | `-1` |
| `5 -3 -2 4` | 5, 2, 0, 4 | no | 4 | `4` |

In the third test the inversions are `(5, 2)`, `(5, 0)`, `(5, 4)` and `(2, 0)`.

> =(info)**Note.**= This matches the statement's sequence of operations `i = 2, 3, 2, 4` for the third test: four swaps in total.

> =(accent)**Important.**= Prefix sums reach about `2 × 10^14` and the inversion count about `2 × 10^10`, so everything is stored in `long long`.

### Code

```cpp
#include <bits/stdc++.h>
long long merge(std::vector<long long> &v, std::vector<long long> &tmpo, int l, int r)
{
    if (r - l <= 1)
        return 0;
    int m = (l + r) / 2;
    long long count = merge(v, tmpo, l, m) + merge(v, tmpo, m, r);
    int i = l, j = m, k = l;
    while (i < m && j < r)
    {
        if (v[i] <= v[j])
            tmpo[k++] = v[i++];
        else
        {
            count += m - i;
            tmpo[k++] = v[j++];
        }
    }
    while (i < m)
        tmpo[k++] = v[i++];
    while (j < r)
        tmpo[k++] = v[j++];
    for (int x = l; x < r; x++)
        v[x] = tmpo[x];
    return count;
}

int main()
{
    int t;
    std::cin >> t;
    while (t--)
    {
        int n;
        std::cin >> n;
        std::vector<long long> s(n), tmpo(n);
        long long cur = 0;
        bool ok = true;
        for (int i = 0; i < n; i++)
        {
            long long x;
            std::cin >> x;
            cur += x;
            s[i] = cur;
            if (cur < 0)
                ok = false;
        }
        if (!ok)
        {
            std::cout << -1 << std::endl;
            continue;
        }
        std::cout << merge(s, tmpo, 0, n) << std::endl;
    }
    return 0;
}
```

### Walkthrough

- `s` : the prefix sums `s[1..n]`, stored from index `0`.
- `cur` : the running prefix sum while reading.
- `ok` : becomes `false` as soon as one prefix sum is negative. In that case the program prints `-1` and skips to the next test.
- `tmpo` : a scratch buffer for merging.
- `merge(v, tmpo, l, r)` : sorts `v[l..r)` and returns the number of inversions inside it.
  - **Base case:** a range of size `0` or `1` has no inversions.
  - **Split:** `m` is the midpoint. The inversions are those fully in the left half, those fully in the right half, and those that cross the middle.
  - **Merge loop:** `i` walks the left half and `j` the right half. If `v[i] <= v[j]` the left element goes first. Otherwise `v[j]` is smaller than all of `v[i..m)`, so `count += m - i`.
  - **Tails:** the two `while` loops copy what is left, and the last `for` copies the merged range back into `v`.
- `merge(s, tmpo, 0, n)` : the inversion count of the whole prefix-sum array, which is the answer.

> =(warn)**Warning.**= The merge step uses `v[i] <= v[j]`, not `<`. This keeps equal values in order and makes sure they are not counted as inversions.

> =(warn)**Warning.**= The helper is named `merge`, which is also a function in `std`. It works here because the code never writes `using namespace std;`. If you add that line, rename the helper, for example to `countInversions`.

> =(ok)**Tip.**= A Fenwick tree over compressed values also counts inversions in `O(n log n)`. Merge sort is shorter because it needs no coordinate compression.

**Complexity:** =(accent)O(n log n)= time per test and =(accent)O(n)= memory.
