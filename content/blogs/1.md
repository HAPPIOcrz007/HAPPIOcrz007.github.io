## Text styling

You can write **bold**, *italic*, ~~strikethrough~~ and `inline code`. Colored text uses the same
syntax as the rest of the site: =(#e8510f)this is orange=, =(#2da44e)this is green= and you can
mix it with **=(#1890ff)bold blue=**.

Links work too — [my GitHub](https://github.com/HAPPIOcrz007) opens in a new tab. To link to
another post on this site, use `[text](#post-2)`.

### Headings don't look like links

Headings are heavy and use the body text color — links inside them stay green and underlined,
so you can tell them apart. Here's a [link inside a heading](#text-styling) to prove it.

## Images

Put images next to the post as `1_1.png`, `1_2.png`, … and reference them by number:

![Caption goes here — click any image to zoom](img:1)

A bare file name works as well, `![alt](1_2.png)`, and so do full URLs.

## Lists

### Unordered

- Unordered item
- Another item
  - A nested item
    - A third level, indented two more spaces
    - Another third-level item
  - Back to the second level
- Last item

### Numbered

1. First step
2. Second step
3. Third step

### Lettered — lowercase

a. Download the toolchain
b. Write a hello-world
c. Compile and run

### Lettered — uppercase

A. Read the problem statement twice
B. Sketch the algorithm on paper
C. Code it, then test the edge cases

### Roman numerals — lowercase

i. Parse the input
ii. Build the graph
iii. Run BFS

### Roman numerals — uppercase

I. Formalize the state space
II. Prove the recurrence
III. Write the DP

### Mixed nesting — any marker, any depth

1. Start with the fundamentals
   a. Syntax and types
      i. Pointers and references
         - Don't fear the `*`
         - Prefer references when you can
      ii. The standard library
         - `std::vector`, `std::map`, `std::set`
   b. Build tooling
      - `g++` flags worth memorizing
      - `make`, `cmake`, and when to reach for each
2. Then move to algorithms
   a. Sorting and searching
   b. Graphs
      i. BFS, DFS, Dijkstra
      ii. Union-Find
3. Then practice

## Quotes, code and tables

> Simplicity is prerequisite for reliability.

Fenced code blocks get a language label, syntax highlighting and a **Copy** button. Put the
language after the opening fence (`cpp`, `python`, `bash`, `js`, `ts`, `json`, `html`, `css`,
`sql`, `java`, `rust`, `go`):

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // fast IO
    ios::sync_with_stdio(false);
    vector<int> v = {3, 1, 2};
    sort(v.begin(), v.end());
    cout << "Hello, blog! " << v[0] << "\n";
}
```

```python
def fib(n: int) -> int:
    """Return the n-th Fibonacci number."""
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(10))  # 55
```

g++ -O2 -std=c++17 main.cpp -o main && ./main < input.txt

## Side-by-side text and image (wiki style)

Two ways to put an image and text next to each other. Both wrap the following
paragraphs around the image, Wikipedia-style.

### Shorthand — `{float=left}`

The simplest form: put `{float=left}` (or `{float=right}`) after an image and the
next paragraph flows around it.

![A floated image](img:2){float=left}

This paragraph is wrapping around the image on its left. Notice how it flows
around the bottom of the image, filling the space beside it rather than
starting underneath. Once the paragraph is tall enough that it clears the
image, the next paragraph will start at the full column width again. On narrow
screens the image drops to full width above the text so nothing gets squeezed
into an unreadable column.

The paragraph after the wrapping one sits at full width, below the float.

### Explicit container — `:::float`

Use the `:::float left` / `:::float right` block when you want a caption, a
code block, or several paragraphs to live inside the float:

:::float right
![A small floated card](img:2){width=200}
:::

This paragraph wraps around the right-side float instead. Using the explicit
container is nicer when the thing you're floating is more than just a bare
image — a figure with a caption, a small table, whatever. The `left` / `right`
keyword after `:::float` controls which side it sticks to.

Full-width paragraph resumes below the float.

## Embeds — click-to-open cards

Embeds don't load the target page into the post. Instead, `{embed=true}` renders
a preview card you click to open the site in a new tab:

![Anthropic](https://www.anthropic.com){embed=true}

Give it a size hint and it still renders as a card — the size only affects the
card, not an iframe:

![cppreference](https://en.cppreference.com){embed=true}

Inline pill form — useful when a link is part of a sentence, like
![this one](https://competitive-programming.dev){embed=true} which points at a
CP-focused site, or ![codeforces](https://codeforces.com){embed=true} for
practice.

## Sizing images

Add `{width=..}` and/or `{height=..}` after an image to cap its size — handy for
icons or wide banners. Give one and the other defaults to auto so the image keeps
its aspect ratio:

![A small icon](img:1){width=64}

A width in percent works too: `{width=50%}`.

## PDFs

PDFs are attached exactly like images: `<blog>_<n>.pdf`. The post shows the first
page; clicking it opens the whole PDF in the browser's PDF viewer in a new tab.

![Attached PDF — click to open the full document](pdf:2){page=1}

Jump straight to a specific page with `{page=N}` — the preview shows that page,
and clicking opens the PDF at that page:

![Second page of the same PDF](pdf:2){page=2}
