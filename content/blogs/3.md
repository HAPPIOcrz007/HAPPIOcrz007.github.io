## A. Same Direction

### Problem in short

House at `0`, supermarket at `a`, station at `b` (`a` and `b` are non-zero and different). Print =(ok)Yes= if both lie on the same side of the house, otherwise =(danger)No=.

### Idea

Two non-zero numbers are on the same side of `0` exactly when they have the =(accent)same sign=. The product of two numbers is positive if and only if their signs match, so the whole problem reduces to checking `a * b > 0`.

| `a` | `b` | `a * b` | Answer |
|-----|-----|---------|--------|
| 40 | -20 | -800 | =(danger)No= |
| -3 | -5 | 15 | =(ok)Yes= |
| 9 | 19 | 171 | =(ok)Yes= |

> =(info)**Note.**= Since `|a|, |b| ≤ 100`, the product is at most `10^4`, so `int` never overflows.

### Code

```cpp
#include <iostream>
int main() {
    int a, b;
    std::cin >> a >> b;
    std::cout << (a * b > 0 ? "Yes" : "No") << std::endl;
    return 0;
}
```

### Walkthrough

- `a`, `b` : the coordinates of the supermarket and the station.
- `a * b > 0 ? "Yes" : "No"` : the ternary operator prints `Yes` when the signs match.

**Complexity:** =(accent)O(1)= time, =(accent)O(1)= memory.

## B. Clogged Faucet or Drain

### Problem in short

There are `n` faucets and `m` drains, and exactly one of them is clogged. `s[i][j]` is `'o'` when water flows from faucet `i` to drain `j`, and `'x'` otherwise. Find the clogged one.

### Idea

- If =(warn)faucet `i`= is clogged, no water leaves it, so the whole row `s[i]` is `x`. Every other row is `o` everywhere.
- If =(cyan)drain `j`= is clogged, no water reaches it, so the whole column `j` is `x`.

> =(accent)**Important.**= Because `n, m ≥ 2`, a clogged drain can never make a whole row `x`: every row still has at least one other column with `o`. So an all-`x` row means a faucet is clogged, and if there is no all-`x` row, the clogged one must be a drain.

So the plan is:

1. Look for a row that is entirely `x`, then print `Faucet i`.
2. Otherwise, look for a column that is entirely `x`, then print `Drain j`.

### Code

```cpp
#include <bits/stdc++.h>
int main()
{
    int n, m;
    std::cin >> n >> m;
    std::vector<std::string> s(n);
    for (int i = 0; i < n; i++)
    {
        std::cin >> s[i];
    }
    for (int i = 0; i < n; i++)
    {
        bool faucet = true;
        for (int j = 0; j < m; j++)
        {
            if (s[i][j] == 'o')
            {
                faucet = false;
                break;
            }
        }
        if (faucet)
        {
            std::cout << "Faucet " << i + 1 << std::endl;
            return 0;
        }
    }
    for (int i = 0; i < m; i++)
    {
        bool drain = true;
        for (int j = 0; j < n; j++)
        {
            if (s[j][i] == 'o')
            {
                drain = false;
                break;
            }
        }
        if (drain)
        {
            std::cout << "Drain " << i + 1 << std::endl;
            return 0;
        }
    }
    return 0;
}
```

### Walkthrough

- `n`, `m` : number of faucets and drains.
- `s` : a `vector<string>` holding the `n` rows, each of length `m`.
- **First loop** (`i` over faucets):
  - `faucet` starts as `true` (assume this row is all `x`).
  - The inner loop over `j` sets `faucet` to `false` and breaks as soon as it sees an `'o'`.
  - If `faucet` is still `true`, row `i` is entirely `x`, so print `Faucet i + 1` (1-indexed output).
- **Second loop** (`i` over drains, here `i` is a column index):
  - `drain` starts as `true`.
  - The inner loop over `j` (rows) checks `s[j][i]`, which is column `i`.
  - If no `'o'` is found, print `Drain i + 1`.
- `return 0;` right after printing ends the program, since the answer is unique.

> =(ok)**Tip.**= Note the swapped indices in the second loop: `s[j][i]` walks =(accent)down= a column, while `s[i][j]` in the first loop walks =(accent)along= a row.

**Complexity:** =(accent)O(N·M)= time, =(accent)O(N·M)= memory for the grid.

## C. Nearest Different Color

### Problem in short

Points `0 … n-1` have colors `a[i]`. For each `i`, print the distance to the nearest point with a color different from `a[i]`. At least two distinct colors exist.

### Idea

The nearest different point is either on the left or on the right, so compute both and take the minimum.

- `l[i]` : distance to the nearest different color =(info)on the left= of `i`.
- `r[i]` : distance to the nearest different color =(warn)on the right= of `i`.

Computing `l[i]` from `l[i-1]`:

- If `a[i-1] != a[i]`, the neighbour itself is different, so `l[i]` becomes `1`.
- Otherwise the two points share the same nearest different point on the left, which is one step further for `i`, so `l[i]` becomes `l[i-1] + 1`. This only applies if `l[i-1]` actually exists (is not `infiity`).

`r[i]` is the mirror image, computed from right to left.

Sample 1 with `a` being `1 1 2 3 3 3`:

| i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| `a[i]` | 1 | 1 | 2 | 3 | 3 | 3 |
| `l[i]` | =(muted)∞= | =(muted)∞= | 1 | 1 | 2 | 3 |
| `r[i]` | 2 | 1 | 1 | =(muted)∞= | =(muted)∞= | =(muted)∞= |
| `min(l, r)` | =(ok)**2**= | =(ok)**1**= | =(ok)**1**= | =(ok)**1**= | =(ok)**2**= | =(ok)**3**= |

> =(info)**Note.**= A value of ∞ simply means no different color on that side. Since at least two colors exist, every position has a finite value on at least one side, so the minimum is always finite.

### Code

```cpp
#include <bits/stdc++.h>
int main()
{
    int infiity = 1000000000;
    int n;
    std::cin >> n;
    std::vector<int> a(n);
    for (int i = 0; i < n; i++)
    {
        std::cin >> a[i];
    }

    std::vector<int> l(n, infiity), r(n, infiity);
    for (int i = 1; i < n; i++)
    {
        if (a[i - 1] != a[i])
        {
            l[i] = 1;
        }
        else if (l[i - 1] != infiity)
        {
            l[i] = l[i - 1] + 1;
        }
    }

    for (int i = n - 2; i >= 0; i--)
    {
        if (a[i + 1] != a[i])
        {
            r[i] = 1;
        }
        else if (r[i + 1] != infiity)
        {
            r[i] = r[i + 1] + 1;
        }
    }
    for (int i = 0; i < n; i++)
    {
        std::cout << std::min(l[i], r[i]);
        if (i + 1 < n)
        {
            std::cout << ' ';
        }
    }
    std::cout << std::endl;
    return 0;
}
```

### Walkthrough

- `infiity` : a large sentinel (`10^9`) meaning not found. The spelling matches the code.
- `a` : the colors.
- `l`, `r` : the left and right distance arrays, both initialised to `infiity`.
- **Left pass** (`i` from `1` to `n-1`): `l[0]` stays `infiity` since nothing lies to its left.
- **Right pass** (`i` from `n-2` down to `0`): `r[n-1]` stays `infiity`. We go backwards so `r[i+1]` is ready when `r[i]` is computed.
- **Output loop:** prints `min(l[i], r[i])`, with a space between values but not after the last one.

> =(warn)**Warning.**= Without the `!= infiity` checks, `infiity + 1` would creep upward and lose its meaning as not found. The check keeps the sentinel clean.

**Complexity:** =(accent)O(N)= time, =(accent)O(N)= memory.

## D. Splitting a String into Three ABC-Complete Parts

### Problem in short

String `s` of length `n` over `A`, `B`, `C`. Choose `1 ≤ i < j < n` and split into `s[1..i]`, `s[i+1..j]`, `s[j+1..n]`. Count the splits where =(accent)each= part contains all of `A`, `B`, `C`.

### Idea

Work with a 1-indexed string (the code prepends a space with `s = " " + s`). Each of the three conditions is a simple threshold.

1. =(ok)**First part**= `s[1..i]` has all three letters exactly when `i ≥ p`, where `p` is the smallest index by which all of `A`, `B`, `C` have appeared.
2. =(cyan)**Last part**= `s[j+1..n]` has all three letters exactly when `j ≤ q`, where `q` is the smallest of the three last positions, minus one.
3. =(warn)**Middle part**= `s[i+1..j]` has all three letters exactly when `j ≥ f`, where `f` is the maximum, over the three letters, of the first occurrence at an index of at least `i+1`.

For a fixed `i ≥ p`, the valid `j` form the range from `f` to `q`, giving `q - f + 1` choices (when that is positive). Sum this over all `i`.

To get `f` quickly we precompute a =(accent)next-occurrence table=: `next[i][c]` is the smallest index at or after `i` whose character is `'A' + c`, or `infiity` if there is none.

> =(info)**Note.**= Copying row `i + 1` and then updating one entry gives each row in constant time, so the whole table costs O(N).

### Worked example (Sample 1)

`s` is `AABCCABCCBCA` and `n` is `12`.

- `p` is `4`: first `A` at 1, first `B` at 3, first `C` at 4, and the maximum is 4.
- last `A` is 12, last `B` is 10, last `C` is 11, so `q` is `10 - 1`, which is `9`.

| `i` | `f` | valid `j` | count |
|-----|-----|-----------|-------|
| 4 | 7 | 7, 8, 9 | 3 |
| 5 | 8 | 8, 9 | 2 |
| 6 | 12 | none, since 12 is above `q` | 0 |
| 7 to 11 | at least 10 | none | 0 |

Total: =(ok)**5**=, which matches the sample output.

### Code

```cpp
#include <bits/stdc++.h>
int main()
{
    int infiity = 1000000000;
    int n;
    std::string s;
    std::cin >> n >> s;
    s = " " + s;

    std::vector<std::vector<int>> next(n + 2, std::vector<int>(3, infiity));
    for (int i = n; i >= 1; i--)
    {
        next[i] = next[i + 1];
        next[i][s[i] - 'A'] = i;
    }

    int p = std::max({next[1][0], next[1][1], next[1][2]});

    int final[3] = {0, 0, 0};
    for (int i = 1; i <= n; i++)
    {
        final[s[i] - 'A'] = i;
    }
    int q = std::min({final[0], final[1], final[2]}) - 1;

    long long result = 0;
    if (p <= n)
    {
        for (int i = p; i <= n - 1; i++)
        {
            int f = std::max({next[i + 1][0], next[i + 1][1], next[i + 1][2]});
            if (f <= q)
            {
                result += q - f + 1;
            }
        }
    }
    std::cout << result << std::endl;
    return 0;
}
```

### Walkthrough

- `s = " " + s;` shifts the string so characters live at indices `1` to `n`.
- `next` : table of size `(n + 2) × 3`. Row `n + 1` is all `infiity`, the base case.
  - Loop `i` from `n` down to `1`: copy row `i + 1`, then set `next[i][s[i] - 'A']` to `i`.
- `p` : the max of `next[1][0]`, `next[1][1]`, `next[1][2]`. If some letter is missing from `s`, this is `infiity`, so `p > n`.
- `final[3]` : last position of `A`, `B`, `C` (initialised to `0`).
- `q` : the min of `final[...]` minus one, the largest `j` that still leaves all three letters in the suffix.
- `result` : the answer, stored in a `long long`.
- **Main loop** (`i` from `p` to `n-1`):
  - `f` is the max of `next[i + 1][0..2]`, the smallest `j` giving a complete middle part.
  - If `f <= q`, add `q - f + 1` valid values of `j`.

> =(warn)**Warning.**= The answer can reach roughly 4.5 × 10^10, which overflows `int`. That is why `result` is a `long long`.

> =(ok)**Tip.**= If a letter is missing from `s`, then `p` is `infiity`, which is above `n`, and the guard `if (p <= n)` skips the loop. If `f` is `infiity`, then `f <= q` fails automatically, so no special-casing is needed.

**Complexity:** =(accent)O(N)= time and =(accent)O(N)= memory (the table holds `3N` integers).

## E. Roads Without Repeating a Color

### Problem in short

There are `n` cities and `m` one-way roads. Road `i` goes from `u[i]` to `v[i]` and has color `c[i]`. Travel from city `1` to city `n` without using two roads of the same color =(danger)in a row=. Print the minimum number of roads used, or `-1` if it is impossible.

### Idea

#### Step 1: the state is the last road used

Knowing only the current city is not enough, because the next road must not match the color of the road we just used. So we run a BFS where each =(accent)state is a road= (the last road traversed). From road `e` arriving at city `v[e]`, we may take any road `f` leaving that city with `c[f] != c[e]`.

#### Step 2: avoid scanning everything again and again

A naive BFS would scan all outgoing roads of a city every time we arrive there. A city with many incoming and outgoing roads would make that too slow. The key observation:

> =(accent)**Important.**= A city only needs to be expanded =(accent)at most twice=, by two arrivals with =(accent)different= colors.

Why this is enough, with `c1` the color of the first arrival at city `x`:

1. =(ok)**First arrival (color `c1`):**= relaxes every outgoing road except those of color `c1`.
2. =(cyan)**Second arrival with a different color `c2`:**= relaxes the outgoing roads of color `c1`, the only ones still untouched.
3. =(muted)**Any later arrival:**= every outgoing road of `x` already has a distance, and BFS processes states in non-decreasing distance order, so those distances are already minimal.

An arrival with the =(accent)same= color as the first one would relax exactly the same set as the first, so it is skipped too. The total work is O(N + M): each city is expanded at most twice, and each expansion scans its adjacency list.

### Code

```cpp
#include <bits/stdc++.h>
int main()
{
    int n, m;
    std::cin >> n >> m;
    std::vector<int> u(m), v(m), c(m);
    std::vector<std::vector<int>> adjacency(n + 1);
    for (int i = 0; i < m; i++)
    {
        std::cin >> u[i] >> v[i] >> c[i];
        adjacency[u[i]].push_back(i);
    }

    std::vector<int> distance(m, -1);
    std::vector<int> count(n + 1, 0), firstColor(n + 1, 0);

    std::queue<int> q;

    count[1] = 2;
    for (int f : adjacency[1])
    {
        distance[f] = 1;
        q.push(f);
        if (v[f] == n)
        {
            std::cout << 1 << std::endl;
            return 0;
        }
    }

    while (!q.empty())
    {
        int e = q.front();
        q.pop();
        int city = v[e];
        if (count[city] >= 2)
        {
            continue;
        }
        if (count[city] == 1 && firstColor[city] == c[e])
        {
            continue;
        }
        if (count[city] == 0)
        {
            firstColor[city] = c[e];
        }
        count[city]++;
        for (int f : adjacency[city])
        {
            if (c[f] == c[e] || distance[f] != -1)
            {
                continue;
            }
            distance[f] = distance[e] + 1;
            if (v[f] == n)
            {
                std::cout << distance[f] << std::endl;
                return 0;
            }
            q.push(f);
        }
    }
    std::cout << -1 << std::endl;
    return 0;
}
```

### Walkthrough

#### Variables

| Variable | Meaning |
|----------|---------|
| `n`, `m` | number of cities and roads |
| `u[i]`, `v[i]`, `c[i]` | start city, end city, and color of road `i` |
| `adjacency[x]` | indices of the roads leaving city `x` |
| `distance[i]` | number of roads used to end on road `i` (`-1` means not reached yet) |
| `count[x]` | how many times city `x` has been expanded (0, 1 or 2) |
| `firstColor[x]` | arrival color of the first expansion of city `x` |
| `q` | BFS queue holding road indices |
| `e` | the road just popped from the queue |
| `f` | a candidate next road leaving `v[e]` |
| `city` | `v[e]`, the city we are standing in after road `e` |

#### Setup

- Every road `i` is appended to `adjacency[u[i]]`, so we can list the roads out of a city.
- =(accent)Starting city.= We have not used any road yet, so there is no color restriction. Every road out of city `1` gets `distance[f]` set to `1` and is pushed. Setting `count[1]` to `2` marks city `1` as fully expanded, so we never expand it again later. If any of these roads already ends at `n`, the answer is `1`.

#### Main loop

1. Pop road `e` and look at `city`, which is `v[e]`.
2. `if (count[city] >= 2) continue;` The city has been expanded by two different colors already, so nothing new is possible.
3. `if (count[city] == 1 && firstColor[city] == c[e]) continue;` This arrival has the same color as the first one, so it would repeat the first expansion. Skip it.
4. If `count[city]` is `0`, store `firstColor[city]` as `c[e]`. Then increment `count[city]`.
5. For every road `f` leaving `city`:
   - skip it if `c[f] == c[e]` (the same color twice in a row is forbidden),
   - skip it if `distance[f] != -1` (already reached, and BFS guarantees it was reached no later),
   - otherwise set `distance[f]` to `distance[e] + 1`,
   - if `v[f] == n`, print `distance[f]` and stop, since BFS reaches `n` first by the shortest route,
   - otherwise push `f` onto `q`.
6. If the queue empties without reaching city `n`, print `-1`.

> =(info)**Note.**= Because BFS runs over roads and every transition costs exactly one road, the first time any road ending at `n` is discovered gives the minimum count. That is why the program can exit early.

> =(warn)**Warning.**= `distance` and `count` are safe here because the code uses `std::` prefixes and has no `using namespace std;`. If you ever add that line, names like `distance` and `count` will clash with standard library functions.

### Worked example (Sample 1)

The shortest route uses roads `1, 2, 5, 4`:

`1 -(c1)-> 2 -(c2)-> 4 -(c3)-> 3 -(c5)-> 6`

The colors `1, 2, 3, 5` never repeat consecutively, and it takes =(ok)**4**= roads, which matches the expected output.

For Sample 2, all roads go from city `1` to city `2`, and city `2` has no outgoing roads, so city `3` is unreachable and the output is =(danger)**-1**=.

**Complexity:** =(accent)O(N + M)= time, =(accent)O(N + M)= memory.
